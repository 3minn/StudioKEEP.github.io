# Studio KEEP 콘텐츠 담당자 인수인계

## 접속과 담당 범위

`https://3minn.github.io/StudioKEEP.github.io/admin/` → 본인 GitHub 계정으로 로그인합니다.
메뉴는 **멤버 / 프로젝트 / 공지사항** 세 가지입니다. HTML, CSS, JavaScript는 수정하지 않습니다.

## 새 항목 등록

1. 메뉴를 고르고 새 항목을 누릅니다.
2. 고유 ID는 `new-film-2026`처럼 영문 소문자·숫자·하이픈으로 입력합니다. **생성 후 ID를 변경하지 않습니다.**
3. 한국어 제목/이름과 내용을 입력합니다. 영어·일본어는 선택이며, 비워두면 한국어가 표시됩니다.
4. 이미지는 업로드 또는 기존 이미지 선택. PNG/JPG/WEBP/GIF, 10MB 이하. 다른 항목이 사용하는 이미지를 임의로 삭제하지 않습니다.
5. `사이트에 공개`를 끄고 저장하면 GitHub에 보관만 됩니다. 켜고 저장하면 자동 배포 후 사이트에 표시됩니다.
6. 저장 후 저장소 Actions에서 최신 배포가 성공했는지 확인하고 실제 사이트를 새로고침합니다.

프로젝트의 `제작 크레딧 · 참여 멤버`를 먼저 선택합니다. 이것이 참여 관계의 기준입니다. 멤버 화면의 대표 참여작은 그 멤버가 크레딧에 있는 공개 프로젝트 중 선택합니다. 나머지 참여작도 자동 연결됩니다.
멤버 비공개/삭제 시 프로젝트 크레딧에서 자동 제외합니다. 프로젝트 비공개/삭제 시 멤버 참여작에서도 제외합니다. 원본의 참조 ID는 보존되므로 재공개하면 다시 연결됩니다.

## 수정·숨김·삭제

- 수정: 항목 열기 → 내용 수정 → 저장.
- 잠시 숨김: 공개 스위치 끄기 → 저장 → 자동 배포 확인. 이미지도 공개 항목이 참조하지 않으면 다음 배포에서 제외됩니다.
- 삭제: 항목 삭제 → 확인 → 배포 확인. 되돌리기는 복구 문서를 따릅니다.
- 표시 순서는 작은 숫자가 먼저입니다. 공지는 최신 날짜가 우선이고 같은 날짜에 표시 순서가 적용됩니다.
- 공지 내용은 일반 텍스트와 줄바꿈을 지원합니다. HTML은 실행되지 않습니다.
- 비공개 스위치는 공개 GitHub 저장소·Git 이력을 숨기지 않습니다. 기밀 자료를 업로드하지 않습니다.

## 관리자 교체·권한 회수 (소유자/기술 담당자)

1. 새 담당자의 정확한 GitHub ID를 확인하고 Collaborator로 초대합니다.
2. Worker ADMIN_LOGINS에 새 계정을 추가하고 재배포합니다.
3. 새 담당자가 직접 로그인·시험 공지 저장·반영을 확인합니다.
4. 이전 담당자의 **저장소 Collaborator 쓰기 권한을 제거**하고 Worker 명단에서도 삭제·재배포합니다. 명단만 지우면 이미 발급된 토큰의 GitHub 쓰기 권한은 사라지지 않습니다.
5. 이전 담당자는 GitHub Settings → Applications → Authorized OAuth Apps에서 Studio KEEP CMS 승인을 취소하고 CMS에서 로그아웃합니다.
6. Cloudflare 계정 권한과 OAuth App 소유·관리 담당도 인계합니다. 비밀키를 공유 문서에 남기지 않습니다. 노출 의심 시 Client Secret·STATE_SECRET을 교체합니다.

두 명 모두 운영 가능한 상태를 유지하고, 계정 복구 정보는 각자 안전하게 관리합니다.

## 인수인계 기록

- 저장소 소유자 / 콘텐츠 담당자 A / 담당자 B의 GitHub ID
- Cloudflare Worker 관리 담당자와 실제 Worker URL
- OAuth App 소유자와 설정 화면 위치 (비밀키 제외)
- 마지막 정상 배포 SHA / Actions 링크 / 실제 사이트 URL
- 미등록 영상 및 CONTACT/JOIN 링크 담당자
- 권한 회수·복구 시험 일자와 결과

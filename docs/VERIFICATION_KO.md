# 검증 기록

## 자동 테스트 범위

`npm test`는 실제 프로젝트 빌드 함수와 실제 HTML 렌더 함수, OAuth Worker 함수를 실행합니다.

- 콘텐츠 등록·수정·비공개·재공개·삭제 후 출력 확인
- 비공개 원문·참조·전용 이미지가 dist에서 빠지는지 확인
- 한글 이미지 파일명, 하위 경로, JSON 스크립트 삽입 방어
- 이미지 경로 이탈·심볼릭 링크·위장 이미지 거부
- 기존 CSS 및 Vket event.js 해시 비교
- 한·영·일 렌더·크레딧 왕복 링크·공지·XSS escaping
- 서명 state·만료·PKCE·쿠키·관리자 명단·write 권한·postMessage origin 검사

OAuth 테스트의 GitHub 응답은 모의 응답입니다. DOM 렌더 테스트도 VM 스텁이며 실제 브라우저의 화면·레이아웃·애니메이션 테스트가 아닙니다. 실제 계정 로그인 성공이나 저장·배포 검증을 대신하지 않습니다.

## 운영 전 필수 실제 시험 (현재 미실시)

OAuth Worker 배포, secrets 설정, 관리자 두 명의 실제 로그인 및 GitHub Pages 설정이 필요합니다.

| 순서 | 동작 | 합격 증거 |
|---|---|---|
| 1 | 관리자 A가 /admin/에 GitHub 로그인 | 멤버/프로젝트/공지 메뉴 표시 |
| 2 | 시험용 멤버·프로젝트·공지 등록, 이미지 업로드 | content/*.json 및 uploads 파일의 커밋 SHA |
| 3 | 프로젝트 크레딧에 시험 멤버 지정 | 실제 프로젝트↔멤버 링크 왕복 |
| 4 | 공개 켜고 저장 | Actions build/deploy/verify-live 성공 및 실사이트 표시 |
| 5 | 관리자 B가 별도 로그인 후 내용 수정 | B의 수정 커밋과 사이트 문구 변경 |
| 6 | 시험 항목 모두 비공개 처리 | 공개 JSON에서 ID·원문 제외, 전용 이미지 URL 404 |
| 7 | 다시 공개 후 삭제 | 재등장 후 재배포 시 삭제, 깨진 참조 없음 |
| 8 | 시험 커밋 revert 및 재배포 | 복구한 데이터·이미지와 SHA 확인 |
| 9 | 권한 회수 시험용 계정의 쓰기 권한 제거 | 재로그인 실패 및 기존 토큰으로 저장 불가 |
| 10 | 데스크톱/모바일·한영일·축소 모션 확인 | LED·블러·홀로그램·커서·필터·Vket·맨위 버튼 확인 |

시험 항목은 `cms-check-*`처럼 명확히 이름을 붙이고 사용자 동의된 시험 콘텐츠만 공개합니다. 실제 작품/멤버를 시험 목적으로 삭제하지 않습니다.

## 실배포 HTTP 검사

```sh
npm run verify:live -- https://3minn.github.io/StudioKEEP.github.io/ <실제-배포-SHA>
```

검사는 index, admin, config, JS, 공개 JSON, 이미지, Worker health와 배포 SHA를 확인합니다. /health만으로 OAuth secrets 정상 여부를 판단하지 않습니다.

## 완료 판단

자동 테스트 성공 ≠ CMS 운영 완료. 위 실제 시험의 커밋 SHA·Actions URL·실제 페이지 결과가 기록된 뒤에만 저장부터 배포까지 검증 완료로 표시합니다.
